📝 Key Points to Remember

  • Solid arrows → extends (class inheritance)   |   Dashed arrows → implements (interface implementation)
  • LinkedList implements both List<E> AND Deque<E> — it's a doubly-linked list that works as a list, queue, and double-ended queue
  • TreeMap implements NavigableMap → SortedMap → Map — keys are always sorted by natural ordering or a custom Comparator
  • HashSet internally uses a HashMap — it stores elements as keys with a dummy value object
  • Vector, Stack & Hashtable are legacy classes (synchronized) — prefer ArrayList, ArrayDeque & HashMap with external synchronization
  • ConcurrentHashMap uses segment-level locking for better concurrent performance than Hashtable
  • The Map hierarchy is completely separate — it does NOT extend Collection or Iterable

🔍 Internal Implementation — How They Work Under the Hood

ArrayList List

  • Backed by: Resizable Object[] array
  • Initial capacity: 10 (default), grows by 50% when full
  • Growth: newCapacity = oldCapacity + (oldCapacity >> 1)
  • Random access: Direct index into array → O(1)
  • Insert at middle: Shifts all elements right → O(n)
  • Null values: ✅ Allowed
// Simplified internal structure Object[] elementData; int size; // get(index) → elementData[index] → O(1) // add(e) → elementData[size++] = e → O(1)* // add(i, e) → System.arraycopy(...) → O(n)

LinkedList List Deque

  • Backed by: Doubly-linked list of Node objects
  • Each node: {item, prev, next}
  • Head/Tail access: O(1) via first and last pointers
  • Random access: Traversal from head/tail → O(n)
  • Memory: Higher per element (object + 2 pointers per node)
  • Null values: ✅ Allowed
// Internal Node structure class Node<E> { E item; Node<E> prev; Node<E> next; } Node<E> first, last; // head & tail pointers

HashMap Map

  • Backed by: Array of buckets (Node[]), each bucket is a linked list or tree
  • Default capacity: 16, load factor: 0.75
  • Hashing: key.hashCode() → spreads with (h ^ h>>>16)
  • Collision handling: Linked list → Red-Black tree (when bucket ≥ 8 nodes)
  • Resize: Doubles capacity when size > capacity × loadFactor
  • Null keys: ✅ One null key allowed, stored in bucket[0]
// Bucket index calculation int index = (n - 1) & hash(key); // Treeify threshold if (bucket.size() >= 8) → convert to Red-Black Tree if (bucket.size() <= 6) → convert back to LinkedList // Resize when: size > capacity × 0.75

TreeMap Map

  • Backed by: Red-Black Tree (self-balancing BST)
  • Guarantees: O(log n) for get, put, remove — always balanced
  • Ordering: Natural order (Comparable) or custom Comparator
  • Range operations: subMap(), headMap(), tailMap() — all efficient
  • Null keys: ❌ Not allowed (needs comparison)
  • No hashing: Uses comparisons, not hashCode()
// Red-Black Tree node class Entry<K,V> { K key; V value; Entry left, right, parent; boolean color; // RED or BLACK } // Tree is always balanced → height ≤ 2·log₂(n+1)

HashSet Set

  • Backed by: A HashMap<E, Object> internally!
  • Dummy value: All keys map to PRESENT = new Object()
  • add(e): Calls map.put(e, PRESENT)
  • contains(e): Calls map.containsKey(e)
  • Uniqueness: Via hashCode() + equals()
  • Null values: ✅ One null element allowed
// HashSet is literally a HashMap wrapper! private HashMap<E, Object> map; private static final Object PRESENT = new Object(); public boolean add(E e) { return map.put(e, PRESENT) == null; }

PriorityQueue Queue

  • Backed by: Binary Min-Heap (stored in an array)
  • Default capacity: 11, grows by 50% (if < 64) or 25%
  • peek(): Returns root (minimum) → O(1)
  • poll(): Removes root, sifts down → O(log n)
  • add(): Adds at end, sifts up → O(log n)
  • Null values: ❌ Not allowed
  • Ordering: Natural order or custom Comparator
// Heap stored as array Object[] queue; // Parent-child relationship: parent(i) = (i - 1) / 2 leftChild(i) = 2 * i + 1 rightChild(i) = 2 * i + 2 // queue[0] is ALWAYS the minimum element

🎯 Top Interview Questions on Growth Factor

  • ❓ ArrayList vs Vector growth? → ArrayList grows by 50%, Vector grows by 100% (doubles)
  • ❓ HashMap initial capacity? → 16 (must be power of 2 for efficient bucket indexing with & operation)
  • ❓ What is load factor 0.75? → When 75% of buckets are filled, HashMap doubles its capacity. It's a balance between time (fewer collisions) and space (less wasted memory)
  • ❓ Why power of 2 for HashMap? → Because index = hash & (n-1) works like modulo but faster. Only works when n is power of 2
  • ❓ Hashtable initial capacity? → 11 (prime number) — unlike HashMap's 16. Hashtable uses % modulo, not & bitwise AND
  • ❓ HashMap treeify threshold? → Bucket converts from LinkedList → Red-Black Tree when ≥ 8 nodes, back to LinkedList when ≤ 6

⚖️ Comparable vs Comparator 🔥 MUST KNOW

Used for sorting objects in Collections.sort(), Arrays.sort(), TreeSet, and TreeMap.

java.lang.Comparable<T> Natural Ordering

  • Meaning: Defines the default sorting order for the class.
  • Method: public int compareTo(T obj)
  • Modification: You MUST modify the original class to implement it.
  • Usage: Collections.sort(list)
  • Example: String, Integer, Date already implement it.
class Employee implements Comparable<Employee> { int id; String name; @Override public int compareTo(Employee other) { // Sort by ID ascending return this.id - other.id; } }

java.util.Comparator<T> Custom Ordering

  • Meaning: Defines a custom or multiple sorting orders.
  • Method: public int compare(T obj1, T obj2)
  • Modification: You do NOT need to modify the original class.
  • Usage: Collections.sort(list, new MyComparator())
  • Example: Sorting Employees by Name, then by Salary.
// Sort by Name alphabetically (using Lambda) Comparator<Employee> nameSorter = (e1, e2) -> e1.name.compareTo(e2.name); // Or using modern Comparator methods: Comparator<Employee> modernSorter = Comparator.comparing(Employee::getName) .thenComparing(Employee::getSalary);

🔢 The Return Logic Rule (Applies to both)

Return Value Meaning Result in Sorting (Ascending)
Negative ( < 0 ) Current object is smaller than other object Current object comes BEFORE
Zero ( == 0 ) Both objects are equal Order doesn't change / treated identically
Positive ( > 0 ) Current object is larger than other object Current object comes AFTER

Trick: For descending order, just swap the variables or multiply the result by -1!
